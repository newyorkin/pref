# pref

Онлайн-преферанс для трёх игроков: стол по приглашению, торговля, розыгрыш и автоматический подсчёт пули. Интерфейс на русском языке.

Проект состоит из независимого игрового движка на TypeScript, сервера HTTP/WebSocket с SQLite и веб-клиента на React.

## Возможности

- Регистрация, вход и создание стола со ссылкой-приглашением.
- Согласование договорённостей перед первой сдачей.
- Контракты от шестерной до десятерной, игры без козыря, мизер и распасы.
- Вист в светлую и в тёмную, полвиста и уход без трёх.
- Пуля, гора, висты, история сдач и выгрузка результатов в текстовый файл.
- Настройки отображения карт, порядка руки и паузы после взятки; они сохраняются в браузере отдельно для каждого игрока.
- Повторное подключение к текущему столу при временном разрыве связи.

**Состояние партий хранится в памяти сервера. После его перезапуска столы и незавершённые партии не восстанавливаются.** SQLite сохраняет пользователей, сессии и журнал команд, но не заменяет сохранение партии.

## Требования

- Node.js 22 или новее; в `.nvmrc` указана ветка 22. Сервер использует встроенный модуль `node:sqlite`.
- pnpm **10.18.3**, как указано в `package.json`.
- Git для получения исходников.
- Docker с Compose — для запуска в контейнере вместо локальной установки Node.js.

Если Corepack доступен в установленном Node.js, включить нужный pnpm можно так:

```sh
corepack enable
corepack prepare pnpm@10.18.3 --activate
pnpm --version
```

Если команды `corepack` нет, установите pnpm 10.18.3 удобным для вашей системы способом.

## Быстрый старт для разработки

```sh
git clone https://github.com/newyorkin/pref.git
cd pref
pnpm install --frozen-lockfile
pnpm dev
```

Откройте [http://localhost:5173](http://localhost:5173).

Команда `pnpm dev` запускает два процесса:

| Процесс | Адрес | Назначение |
| --- | --- | --- |
| Vite | `http://localhost:5173` | Интерфейс и обновление клиента при изменении кода |
| Сервер | `http://127.0.0.1:3001` | HTTP API, WebSocket и SQLite |

Vite проксирует запросы API и `/ws` на сервер. Адрес прокси задан в [packages/web/vite.config.ts](packages/web/vite.config.ts); если меняете порт сервера, обновите и его.

Если ваша версия Node.js требует флаг для `node:sqlite`, задайте `NODE_OPTIONS=--experimental-sqlite` перед запуском. Например, в PowerShell:

```powershell
$env:NODE_OPTIONS = "--experimental-sqlite"
pnpm dev
```

### Как начать игру

1. Зарегистрируйтесь и войдите. Пароль должен содержать не менее восьми символов, цифру и символ, не являющийся буквой или цифрой.
2. Создайте стол, выбрав длину пули и договорённости.
3. Передайте ссылку-приглашение двум другим игрокам. Каждый входит под своим именем и занимает свободное место.
4. Приглашённые игроки подтверждают договорённости. Если хозяин изменит настройки, подтверждения сбросятся.
5. После двух подтверждений хозяин запускает первую сдачу. С этого момента настройки стола заблокированы.
6. Выполняйте доступные действия на столе. Сервер проверяет очередь хода и допустимость каждого действия.

Для проверки втроём на одном компьютере используйте отдельные профили браузера или разные браузеры: вкладки одного профиля используют общую сессию.

## Запуск через Docker

Из корня репозитория:

```sh
docker compose up --build -d
docker compose logs -f pref
```

Откройте [http://localhost:3001](http://localhost:3001). Контейнер собирает клиент и раздаёт интерфейс, HTTP API и WebSocket с одного порта.

SQLite находится в `/data/pref.sqlite`. Каталог `/data` подключён к именованному тому Compose `pref-data`.

Остановка:

```sh
docker compose down
```

Эта команда сохраняет том с БД. Команда `docker compose down -v` удаляет и том, включая учётные записи и сессии. При любой остановке процесса состояние текущих партий теряется.

## Сборка и запуск без Vite

Сначала установите зависимости, затем соберите клиент:

```sh
pnpm --filter @pref/web build
```

Пример запуска из корня репозитория в PowerShell:

```powershell
$env:STATIC_DIR = (Resolve-Path .\packages\web\dist).Path
$env:DATABASE_PATH = Join-Path $PWD.Path "pref.sqlite"
$env:HOST = "127.0.0.1"
$env:PORT = "3001"
$env:NODE_OPTIONS = "--experimental-sqlite"
pnpm --filter @pref/server start
```

Откройте [http://localhost:3001](http://localhost:3001). Сервер запускается через `tsx`; отдельной команды компиляции серверного пакета сейчас нет.

## Конфигурация сервера

Переменные окружения читает [packages/server/src/main.ts](packages/server/src/main.ts). Автоматическая загрузка `.env` не настроена: задавайте переменные средствами оболочки или Compose.

| Переменная | По умолчанию при локальном запуске | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Адрес прослушивания |
| `PORT` | `3001` | Порт HTTP и WebSocket |
| `DATABASE_PATH` | `pref.sqlite` | Путь к SQLite; относительный путь считается от рабочего каталога серверного процесса |
| `STATIC_DIR` | Не задана | Каталог собранного клиента; без него сервер не раздаёт интерфейс |

При `pnpm --filter @pref/server start` или `dev` рабочим каталогом является `packages/server`. Абсолютные пути позволяют явно выбрать расположение БД и сборки клиента.

В Docker используются `HOST=0.0.0.0`, `DATABASE_PATH=/data/pref.sqlite` и `STATIC_DIR=/app/packages/web/dist`.

## Правила и договорённости

Ниже описаны правила, реализованные в проекте. Выбор готовой разновидности «Сочи», «Питер» или «Ростов» в интерфейсе не предусмотрен.

### Основные правила

- Колода из 32 карт: от семёрки до туза. Три руки по десять карт и прикуп из двух карт.
- В торговле масти возрастают в порядке ♠, ♣, ♦, ♥, затем без козыря. Новая контрактная заявка должна быть выше предыдущей.
- Мизер перебивает заявки до восьмерной включительно; перебить мизер можно девятерной или десятерной. Игрок, уже заявлявший контракт, не может затем заявить мизер.
- После покупки прикупа разыгрывающий сносит две карты и заказывает игру не ниже допустимого уровня.
- Три паса до первой заявки приводят к распасам.
- В розыгрыше нужно давать в масть; при её отсутствии — класть козырь, если он есть. Перебивать старшим козырем необязательно.
- При одном вистующем доступен выбор света или темноты. В светлую вистующий управляет также открытой рукой пасующего; при двух вистующих игра идёт в тёмную.
- Полвиста доступно второму защитнику на шестерной или семерной после паса первого. Первый защитник может принять полвиста пасом или вернуть обычный вист.
- На распасах карты прикупа задают масть первых двух ходов; сами карты прикупа не участвуют во взятках.

### Настройки стола

| Поле | Значения | По умолчанию |
| --- | --- | --- |
| `bulletTarget` | Целая длина пули от 3 до 10000 | `10` |
| `raspasProgression` | `111`, `122`, `123`, `123123` | `111` |
| `raspasExit` | `666`, `677`, `788`, `678678` | `666` |
| `throwTalon` | Договорённость «бросить прикуп в лицо» | `false` |

Прогрессия задаёт множитель последовательных распасов:

| Значение | Множители |
| --- | --- |
| `111` | 1, 1, 1, … |
| `122` | 1, 2, 2, … |
| `123` | 1, 2, 3, 3, … |
| `123123` | 1, 2, 3, 1, 2, 3, … |

Выход задаёт минимальный уровень заказа по мере накопления распасов:

| Значение | До распасов | После 1-го | После 2-го | После 3-го и далее |
| --- | --- | --- | --- | --- |
| `666` | 6 | 6 | 6 | 6 |
| `677` | 6 | 7 | 7 | 7 |
| `788` | 6 | 7 | 8 | 8 |
| `678678` | 6 | 7 | 8 | Повтор 6, 7, 8, … |

Успешный контракт требуемого уровня или сыгранный мизер сбрасывает индекс распасов. Подсад этого не делает.

При включённом `throwTalon` открытые на контрактной игре тузы прикупа дают сдающему по одному очку в пулю. Разыгрывающий, который не является сдающим, может бросить прикуп: тогда сдающему записываются два очка в гору. В мизере и распасах запись за тузов не применяется.

В форме также показаны фиксированные договорённости: первый ход в тёмную, жлобский вист и проверяемая десятерная включены; «Сталинград» выключен. Эти пункты сейчас не редактируются.

### Подсчёт

| Контракт | Цена игры | Обязательство защиты по взяткам |
| --- | --- | --- |
| 6 | 2 | 4 |
| 7 | 4 | 2 |
| 8 | 6 | 1 |
| 9 | 8 | 1 |
| 10 | 10 | 0 |

Сыгранный мизер даёт 10 очков в пулю, каждая взятая на мизере взятка — 10 очков в гору. На распасах перед применением множителя из числа взяток каждого игрока вычитается минимальное число взяток за столом; игрок без взяток получает множитель в пулю.

Партия завершается, когда все трое заполнят пулю. Переполнение пули, помощь другим игрокам, ответственность вистующих и итоговый расчёт реализованы в [scoring.ts](packages/engine/src/scoring.ts). Конкретные примеры записей находятся в [scoring.test.ts](packages/engine/src/scoring.test.ts).

## Структура проекта

```text
packages/
  engine/   Игровые правила, переходы состояния, подсчёт и представления для мест
  server/   HTTP API, WebSocket, пользователи, сессии и журнал команд в SQLite
  web/      React-интерфейс, Vite, настройки отображения и изображения карт
skins/      Исходные изображения для карточных оформлений
```

Движок не зависит от React и сети. Сервер применяет действия к состоянию игры и рассылает каждому игроку представление для его места, скрывая чужие закрытые карты. Клиент показывает доступные действия из серверного состояния.

### HTTP и WebSocket

Основные HTTP-маршруты:

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/register` | Создать пользователя: `{ name, password }` |
| POST | `/login` | Войти и получить cookie сессии: `{ name, password }` |
| POST | `/logout` | Завершить сессию |
| GET | `/me` | Получить текущего пользователя |
| POST | `/tables` | Создать стол с настройками |
| GET | `/tables/:id` | Получить сведения о столе |
| POST | `/tables/:id/join` | Занять свободное место |
| PATCH | `/tables/:id` | Изменить настройки до сдачи; доступно хозяину |
| POST | `/tables/:id/confirm` | Подтвердить договорённости приглашённому игроку |
| POST | `/tables/:id/deal` | Начать игру; доступно хозяину после подтверждений |

Кроме регистрации и входа, маршруты работы со столом требуют сессии. Ссылка интерфейса `/table/:id` отличается от HTTP API `/tables/:id`.

Клиент подключается к WebSocket по `/ws` с cookie сессии. Сообщения `watch` используются для ожидания сдачи, `join` — для подключения к игре. Игровые команды `gameAction` содержат `tableId`, `seat` (0, 1 или 2), уникальный `actionId`, `expectedVersion` и `payload.action`. Сервер также поддерживает `playCard` для отдельного состояния розыгрыша.

Сервер отправляет сообщения `table`, `snapshot` и `rejected`. Версия меняется после принятого действия. Уже обработанный `actionId` позволяет распознать повтор команды; устаревший `expectedVersion` приводит к отказу. Типы сообщений и проверки находятся в [packages/server/src/index.ts](packages/server/src/index.ts).

## Тестирование

Все тесты:

```sh
pnpm test
```

Отдельные пакеты:

```sh
pnpm --filter @pref/engine test
pnpm --filter @pref/server test
pnpm --filter @pref/web test
```

Используется Vitest; тесты лежат рядом с исходниками в файлах `*.test.ts` и `*.test.tsx`.

- **Движок:** колода, торговля, снос, вист, розыгрыш, мизер, распасы и подсчёт пули.
- **Сервер:** реальные HTTP-запросы и WebSocket-соединения, права на места, повтор команд, рассылка состояния и переподключение.
- **Клиент:** преимущественно статическая HTML-разметка компонентов и отдельные функции состояния и отображения. Эти проверки не заменяют взаимодействие с интерфейсом в браузере.

В репозитории пока нет сквозных браузерных тестов, настройки CI, зависимости для измерения покрытия и порогов покрытия. Команды сборки и запуска тестов также не выполняют отдельную полную проверку типов TypeScript.

## Данные и ограничения

| Данные | Хранилище | После перезапуска сервера |
| --- | --- | --- |
| Пользователи и хеши паролей | SQLite, `users` | Сохраняются при сохранении файла БД |
| Сессии | SQLite, `sessions` | Сохраняются при сохранении файла БД |
| Журнал игровых команд | SQLite, `command_log` | Сохраняется, но автоматически не восстанавливает партию |
| Столы, места, настройки и состояние партий | Память процесса | Теряются |
| Настройки отображения игрока | `localStorage` браузера | Сохраняются в этом браузере |

Текущее устройство сервера предполагает один процесс с общим состоянием столов. Несколько экземпляров сервера не синхронизируют партии между собой. Временный обрыв соединения клиента и перезапуск сервера имеют разное поведение: переподключение клиента поддерживается, восстановление партии после перезапуска — нет.
